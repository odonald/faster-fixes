---
title: GitHub integration setup
description: Set up the Faster Fixes GitHub integration to automatically create GitHub issues from feedback and sync status bidirectionally.
---

Faster Fixes integrates with GitHub to automatically create issues when new feedback is submitted and sync status changes between the dashboard and GitHub. For a product overview, see the [GitHub integration overview](/integrations/github).

## Setup

1. Go to **[Application Settings](/integrations) → Integrations** from the sidebar
2. Install the Faster Fixes GitHub App and select which repositories to grant access to. GitHub sends you back to the dashboard and the installation is connected to the organization you are in.
3. In **[Project Settings](/settings) → GitHub**, link your project to a repository

### Several organizations, one GitHub account

A GitHub App can be installed only once per GitHub account or GitHub organization, and GitHub's install page just reopens an existing installation. If you run several organizations on this instance (for example two companies whose repositories live under the same GitHub account), connect the existing installation instead: on the Integrations page of the second organization, the already-installed accounts are listed with a **Use this installation** button. The same installation can serve any number of organizations; each links its own projects to repositories.

## Auto-create issues

When enabled (on by default), new feedback automatically creates a GitHub issue in the linked repository. The issue includes:

- Feedback comment
- Page URL
- DOM selector
- Browser info
- Link to the screenshot
- Console logs and network requests (in a collapsible section)

## Default labels

Issues are tagged with `faster-fixes` by default. You can customize labels in the GitHub link settings.

## Bidirectional status sync

Status changes propagate in both directions:

| Action | Result |
|--------|--------|
| Feedback marked **resolved** or **closed** in dashboard | GitHub issue is closed |
| Feedback marked **new** or **in_progress** in dashboard | GitHub issue is reopened |
| GitHub issue **closed** | Feedback status updated to closed |
| GitHub issue **reopened** | Feedback status updated to new |

## Manual issue creation

You can create a GitHub issue manually from any feedback item in the Inbox using the **Create Issue** action.

## Unlinking

You can unlink a repository from **[Project Settings](/settings) → GitHub** at any time. Existing issue links are preserved but sync stops.
